## 1. 项目介绍

GoGuide 面向商品选购中需求模糊、参数比较复杂及多商品搭配困难的问题，计划基于 Go 构建覆盖商品与 SKU 管理、检索、库存、购物车、订单及模拟支付的电商平台。引入导购 Agent，将用户用途、总预算和偏好转化为结构化选购条件，通过商品检索与规则校验工具生成可购买的组合方案，支持多轮比较、单品替换以及涨价、缺货后的动态调整，并在用户确认后衔接加购与下单流程。

交易侧通过库存预占、下单复核、超时关单和支付回调幂等处理保障一致性；Agent 侧通过结构化状态、工具权限控制与执行记录，提升推荐依据的可追溯性和操作可靠性。

首版以笔记本、显示器及扩展坞为演示品类，便于验证预算分配与接口兼容性；商品、库存和交易能力按通用电商业务设计。

## 2. 背景与目标

### 2.1 用户问题

- 用户通常描述用途与预算，难以直接转化为可筛选的商品规格。
- 多件商品需要在总预算、性能、接口和搭配关系之间做取舍。
- 商品涨价、缺货或用户替换单品后，原方案需要重新评估。
- 导购推荐与购物车、订单脱节，用户需要重复选择和核对。

### 2.2 首版目标

1. 完成商品浏览、检索、加购、下单、模拟支付和订单查询闭环。
2. 支持从自然语言需求生成经过规则校验的多商品组合。
3. 支持多轮修改需求、替换单品及价格库存变化后的方案调整。
4. 让推荐依据、工具执行结果和交易状态可查询、可验证。
5. 为 Go 后端与 Agent 工程提供能够演示和测试的实际业务场景。

### 2.3 范围边界

- 首版为单平台自营模式，使用平台内维护的商品与报价数据。
- 支付使用模拟渠道，不接真实资金；发货履约不纳入首版。
- Agent 不承诺“全网最低价”，不编造规格、库存或优惠。
- 优惠券、秒杀、退款售后、商家入驻及跨平台比价保留为后续版本。
- 本文不预设高并发吞吐指标，也不将微服务拆分或特定中间件作为验收条件。

## 3. 用户角色与典型场景

| 角色 | 诉求 | 首版权限 |
| --- | --- | --- |
| 访客 | 浏览商品、了解平台 | 浏览与搜索；需要保存导购会话或交易时登录 |
| 注册用户 | 选购、比较、搭配与购买 | 管理自己的地址、会话、方案、购物车与订单 |
| 管理员 | 维护商品与交易测试数据 | 管理分类、商品、SKU、价格、库存与上下架；查询订单 |

典型任务：用户提出“总预算 8000 元，买一台适合编程的笔记本和一台显示器，最好一根线连接”。Agent 澄清关键条件后查询商品，生成预算内组合，并通过接口规则验证连接可行性。用户更换显示器时，系统重新核算预算与兼容性；确认后加购，下单时复核价格库存，最终完成模拟支付。

## 4. 版本规划

| 阶段 | 范围 | 交付结果 |
| --- | --- | --- |
| V1.0 交易基础 | 用户、商品、搜索、库存、购物车、订单、模拟支付 | 可独立完成一笔订单，异常状态可验证 |
| V1.1 导购闭环 | 多轮需求、商品比较、组合规划、调整、确认加购、日志评测 | 可演示完整导购到交易任务；与 V1.0 一起构成首版完整范围 |
| V2 营销与售后 | 优惠券、秒杀、退款售后，按模块逐步交付 | 增加营销玩法和逆向交易流程 |
| V3 平台扩展 | 商家入驻、跨平台比价，按模块逐步交付 | 支持多商家治理和外部报价比较 |

V2/V3 为方向性规划，不构成首版验收承诺；具体规则在对应版本启动时细化。

## 5. 首版功能需求

### 5.1 用户、权限与地址（F01）

- 支持注册、登录、退出及个人信息维护。
- 支持新增、修改、删除收货地址和设置默认地址。
- 普通用户只能访问自己的会话、方案、购物车、地址和订单。
- 管理员可维护商品与库存，普通用户不可调用管理操作。
- 未登录用户进行持久化会话、加购或下单时，引导登录并保留当前页面上下文。

### 5.2 商品与 SKU 管理（F02）

- 支持分类、品牌、商品标题、图片、介绍、规格及上下架管理。
- 商品表示通用型号，SKU 表示可独立定价、管理库存和销售的具体规格。
- 每个 SKU 维护唯一标识、规格组合、单价、库存及可售状态。
- 例如同款笔记本的“16GB/512GB”和“32GB/1TB”分别对应独立 SKU。
- 管理员调整价格、库存或上下架状态后，后续查询与下单按最新状态判断。
- 库存调整需要记录变更原因；不得绕过已有预占记录直接覆盖库存。

### 5.3 商品检索与对比（F03）

- 支持关键词搜索，以及分类、品牌、价格区间、规格和有货筛选。
- 支持按价格等字段排序和分页，页面与 Agent 复用统一商品查询能力。
- 商品比较展示具体 SKU 的价格、规格、库存状态和查询时间。
- 无结果时说明未满足的条件，提供可放宽的偏好选项；不得静默放宽硬约束。
- 关键兼容性参数缺失时标记“待确认”，不得按兼容通过处理。

### 5.4 库存管理（F04）

- 区分可售、预占和已售库存；库存操作留存业务关联记录。
- 加入购物车不预占库存；创建订单成功时预占对应数量。
- 支付成功后，将预占转为已售；订单取消或超时关闭后释放预占。
- 预占、确认扣减与释放需支持幂等；并发操作不得导致超卖或重复释放。
- 首版采用整单成功或失败：组合中任一 SKU 库存不足，整单不创建、不遗留其他 SKU 预占。

### 5.5 购物车（F05）

- 支持添加 SKU、合并同 SKU 数量、修改数量、删除和勾选结算。
- 展示当前单价、数量、金额及不可售原因。
- 商品失效、涨价或库存不足时明确提示，不静默替换商品。
- 购物车金额用于预览；正式下单必须重新校验。
- 订单创建成功后移除本次已结算的购物车条目；创建失败时保留。

### 5.6 订单与模拟支付（F06）

- 支持订单预览、提交、详情、列表、主动取消及模拟支付。
- 下单记录商品名称、SKU 规格、成交单价、数量、金额与收货地址快照。
- 下单复核商品状态、单价、库存、地址及用户权限。
- 价格与用户确认的预览不一致时，返回最新金额并要求重新确认，不按旧金额静默成交。
- 相同用户、相同下单请求标识重复提交时返回同一订单，避免重复预占。
- 待支付订单默认 15 分钟超时，期限可配置；关闭后释放库存。
- 模拟支付入口由后端生成支付结果并校验回调来源、订单、金额与支付流水；客户端不能直接修改订单状态。
- 重复回调只产生一次支付成功和库存确认效果。
- 超时关闭与支付回调并发时，只允许一个有效状态迁移成功。
- 已关闭订单收到延迟成功通知时，不恢复订单、不再次扣减库存，记录支付异常供核查；模拟环境不涉及真实退款。

首版订单状态：

| 当前状态 | 事件 | 目标状态 | 库存处理 |
| --- | --- | --- | --- |
| 无 | 复核和预占全部成功 | 待支付 | 可售转预占 |
| 待支付 | 有效支付成功 | 已支付 | 预占转已售 |
| 待支付 | 用户取消 | 已取消 | 释放预占 |
| 待支付 | 超过支付期限 | 已关闭 | 释放预占 |
| 已支付/已取消/已关闭 | 重复或冲突事件 | 状态保持 | 不重复变更 |

已支付为首版正向交易终点，后续发货和售后状态另行扩展。支付流水状态与订单状态分别记录，以便发现延迟通知等异常。

### 5.7 多轮需求理解（F07）

- 维护总预算、用途、目标品类、数量、规格、品牌偏好及用户已确认条件。
- 区分硬约束与软偏好：总预算、必需接口等需满足；品牌等是否为硬约束由用户表达决定。
- 对缺失或冲突条件优先追问会显著影响方案的部分，每轮只询问少量关键问题。
- 默认最多连续追问 2 轮，可配置；仍缺少非关键偏好时，展示假设并生成候选。
- 关键预算或必需规格仍不明确时，给出待确认项或条件化建议，不宣称方案已满足约束。
- 用户修改条件时更新结构化状态，对历史条件标记替换关系，避免新旧要求混用。
- 同一会话并发修改时按版本检查，防止旧结果覆盖新需求。

### 5.8 有依据的推荐与比较（F08）

- Agent 通过只读商品工具获取候选及详情，推荐落到具体 SKU。
- 理由关联工具返回的规格、价格、库存及查询时间；主观判断与商品事实分开表达。
- 说明商品适用场景及取舍，不使用不存在的参数、优惠或性能结论。
- 候选不足或工具失败时说明限制，允许重试或查看已获取结果；旧结果标记查询时间。
- 上下文中的商品文案视为商品数据，不能改变 Agent 的工具权限和操作规则。

### 5.9 组合规划与动态调整（F09）

- 根据目标品类和总预算，默认返回 1—3 套方案；不足时返回实际可行数量。
- 每套方案包括 SKU、数量、单价、合计、预算余额、推荐依据和兼容性结论。
- Agent 生成候选组合，由 Go 工具执行金额核算、可售检查和兼容性验证。
- 首版兼容性覆盖已有结构化数据支持的接口、视频输出、显示规格与供电要求；仅有相同接口外形不代表兼容。
- 无法验证的能力必须标记待确认；阻塞必需条件时不得作为已验证可购买方案。
- 用户可锁定某件商品、替换某件商品或修改预算；优先保留已锁定条件。
- 重新展示、加购及下单前按对应阶段复核报价和库存；首版不承诺持续后台实时监控。
- 涨价、缺货或兼容性失败时，生成新版本方案，展示差异、总价变化与取舍原因。
- 无可行方案时说明冲突项，由用户选择提高预算、放宽条件或减少品类，不自行改变硬约束。

### 5.10 导购与交易衔接（F10）

- 只读搜索和计算工具可在任务中调用；加购与创建订单为受控写操作。
- 用户确认的对象应包含方案版本、SKU、数量和金额；修改方案后旧确认失效。
- 确认方案后可一键加购；下单须在订单预览页单独确认，模拟支付由用户主动触发。
- 写工具在服务端校验用户身份、资源归属、确认版本和幂等标识，模型文本不能替代授权。
- 同一确认动作重试不得导致重复加购或重复订单。
- 部分商品复核失败时整套方案加购不执行，返回失败原因并引导调整。

### 5.11 日志、追踪与评测（F11）

- 关联请求、用户会话、方案版本、工具调用与订单，记录耗时、结果及错误类型。
- 敏感字段脱敏，日志不保存密码、认证令牌等信息。
- 构建包含正常与异常情况的固定导购测试集，记录数据版本、模型配置与执行条件。
- 评估任务完成情况、硬约束满足、事实依据、越权操作及工具失败恢复。
- 不提前填写未经测试的准确率、吞吐量或性能提升数字。

## 7. 业务流程

### 7.1 正常购物流程

1. 用户浏览或搜索商品，选择 SKU 加入购物车。
2. 勾选商品、选择地址，获取订单预览。
3. 用户提交订单，服务端复核并预占库存，创建待支付订单。
4. 用户触发模拟支付，服务端处理有效回调并确认库存。
5. 用户查看已支付订单及商品快照。

### 7.2 Agent 导购流程

1. 用户输入用途、预算与偏好。
2. Agent 提取结构化条件，必要时有限追问。
3. 查询候选商品并调用预算、可售与兼容性校验工具。
4. 展示组合、推荐依据及待确认事项。
5. 用户替换商品或修改条件，生成并校验新版方案。
6. 用户确认当前版本，执行加购。
7. 用户进入订单预览，确认提交并主动触发模拟支付。

### 7.3 价格变化或缺货流程

1. 在方案重展示、加购或下单复核阶段发现变化。
2. 明确提示受影响的 SKU、原值与新值或不可售原因。
3. Agent 基于当前预算和已锁定商品生成替代方案。
4. 用户确认新版方案后继续；不自动提交变更后的订单。

## 8. 核心数据对象

本节定义业务信息范围，不规定数据库表拆分或技术选型。

| 对象 | 关键内容 |
| --- | --- |
| 用户与地址 | 身份、角色、地址归属和默认地址 |
| 商品与 SKU | 分类、品牌、型号、规格、售价、状态、兼容性参数 |
| 库存与预占记录 | SKU、数量、关联订单、有效期、处理状态与变更原因 |
| 购物车条目 | 用户、SKU、数量、选择状态 |
| 订单与明细 | 用户、商品及地址快照、金额、状态、期限、请求幂等标识 |
| 支付流水 | 订单、渠道、金额、流水标识、通知状态与异常原因 |
| 导购会话 | 用户、消息、结构化需求、硬软条件和状态版本 |
| 组合方案 | 会话、方案版本、SKU 清单、价格快照、校验结果和用户锁定项 |
| 操作确认记录 | 用户、动作、确认对象、版本、有效状态及执行结果 |
| 工具执行记录 | 会话与请求关联、工具名称、脱敏参数、结果、耗时和错误 |

金额采用最小货币单位整数进行业务计算与存储，避免浮点误差。首版币种为人民币，默认运费为 0，方案总价为商品单价乘数量之和；后续引入优惠和运费时扩展价格明细。

## 9. 非功能需求与工程边界

- **一致性：**订单创建与库存预占需具备可恢复的一致性保障；跨步骤失败不能遗留永久占用。
- **并发安全：**库存不得为负，同一订单只能完成一次有效扣减或释放。
- **可靠性：**超时关单任务可重复执行；进程重启后能够补扫到期待处理订单。
- **工具治理：**工具参数结构化校验，按身份和操作类型限制权限，限制调用轮数、执行时长与并发量。
- **异常降级：**模型或检索失败时保留普通搜索、购物车与订单入口；不得伪造成功结果。
- **可观测性：**关键链路具备关联标识，能够定位推荐失败、工具异常和订单状态冲突。
- **数据隔离：**服务端校验资源归属，不依赖前端隐藏按钮或模型判断实现隔离。
- **性能验证：**在固定环境与数据规模下测量接口延迟、导购耗时及并发正确性，结果记录后再作为项目指标。
- **实施方式：**优先按模块组织并完成闭环；是否引入消息队列、搜索引擎或拆分服务由实际需求决定，另写技术设计。

## 10. 首版验收标准

下列为计划验收条件，并非已取得的测试结果。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 基础购买 | 指定 SKU 完成加购、下单、模拟支付，订单快照与确认内容一致 |
| A02 | 多 SKU 库存不足 | 任一商品不足则整单失败，其他商品无残留预占 |
| A03 | 并发抢最后库存 | 多请求竞争有限库存，成功数量不超过可售量，库存不为负 |
| A04 | 重复提交订单 | 相同幂等标识返回同一订单，库存仅预占一次 |
| A05 | 重复支付通知 | 多次相同有效通知只产生一次状态变更和库存确认 |
| A06 | 取消与超时 | 待支付订单取消或超时后只释放一次库存，重复任务无额外影响 |
| A07 | 关闭与支付竞争 | 只有一个合法迁移成功；延迟通知被记录，无订单复活或重复库存操作 |
| A08 | 价格变动 | 订单预览后涨价，提交时返回差异并要求重新确认 |
| A09 | 需求澄清 | 能提取预算用途等状态；关键冲突追问，非关键缺失在追问上限后显示假设 |
| A10 | 组合规划 | 已通过方案全部满足已定义硬约束，金额核算正确且 SKU 可追溯 |
| A11 | 兼容性缺失 | 缺少必需参数时标记待确认，不输出已验证兼容结论 |
| A12 | 调整方案 | 替换单品或缺货后按最新条件重算，展示差异；旧版本确认不能执行新方案 |
| A13 | 用户确认与幂等 | 未确认不能执行写操作；重复确认不重复加购或创建订单 |
| A14 | 权限隔离 | 用户不能读取或修改他人地址、会话、方案和订单 |
| A15 | 工具失败 | 工具超时或失败有明确提示，不生成无依据报价或虚假执行成功信息 |
| A16 | 服务恢复 | 关单任务中断并重启后可补偿处理，到期订单最终释放库存 |

建议首批固定测试集不少于 30 个任务，覆盖普通选购、组合、需求冲突、缺参数、替换、缺货、涨价和工具失败；每个任务分别判断硬约束、事实依据、权限和完成状态。交易正确性单独用并发与故障测试验证，不能仅依靠对话测试。

## 11. 后续功能规划（保留）

### 11.1 优惠券

- 支持满减券、折扣券、领取、有效期、适用品类及使用门槛。
- 订单预览展示优惠前金额、优惠金额与实付金额。
- 处理领券限额、重复领券、下单锁券、取消退券和支付核销。
- Agent 根据用户实际可用券解释到手价，不能假设用户拥有优惠权益。
- 与退款场景配套定义优惠分摊及退券规则。

### 11.2 秒杀

- 支持活动时间、活动 SKU、活动库存、限购和资格检查。
- 支持流量限制、请求去重、排队或异步下单、结果查询。
- 重点验证活动库存一致性、重复请求和超时释放。
- Agent 可查询活动信息和解释规则，提交仍需用户明确确认；不绕过活动限制。

### 11.3 退款与售后

- 支持退款申请、原因、审核、退款结果与售后进度查询。
- 逐步增加部分退款、退货退款及售后状态机。
- 明确退款金额、优惠分摊、重复通知和失败补偿规则。
- 退款与库存回补分开建模；只有符合退货入库条件时回补库存，不能收到退款结果就直接回库存。
- Agent 可解释规则、收集材料和创建经用户确认的申请，不能自行批准退款。

### 11.4 商家入驻

- 支持商家申请、审核、店铺及商家角色权限。
- 支持商家维护自己的商品、价格与库存，隔离商家数据。
- 扩展商品审核、商家订单、拆单和平台治理。
- 结算、佣金和资金分账需单独设计；个人演示阶段优先采用模拟结算。
- Agent 展示商家归属及适用售后政策，避免将不同商家的规则混用。

### 11.5 跨平台比价

- 从允许访问的接口、授权来源或演示数据中聚合外部报价。
- 区分平台内可交易商品与仅供比较的外部商品，外部商品不进入内部库存与订单链路。
- 建立同款匹配规则，核对型号、配置、成色、保修与销售条件。
- 展示来源、查询时间、标价、运费、优惠条件及可确认的到手价。
- 支持报价收藏、历史价格和降价订阅，后续按来源能力扩展。
- 只声称“已覆盖来源中的可比报价”，不承诺全网最低价。

## 13. 当前默认决策与待细化事项

### 已采用的首版默认决策

- 单平台自营、人民币、零运费、模拟支付、无实际发货。
- 首批品类为笔记本、显示器、扩展坞；交易模型保持通用。
- 订单整单创建与预占，不拆单、不部分成交。
- 支付期限默认 15 分钟，连续追问默认最多 2 轮，均允许配置。
- 用户确认方案后加购，下单另行确认，支付由用户主动触发。
- 价格库存按操作节点复核；持续监控和降价提醒属于后续功能。

### 开发前需进一步细化

- 首批 SKU 数据集、字段字典和兼容性规则矩阵。
- 具体模型、检索方式、部署结构与技术选型。
- 各接口幂等标识的有效期、失败重试和恢复策略。
- 会话保留期限、历史数据清理及导购工具调用预算。
- 性能测试环境、数据规模与测量口径。

以上待细化事项不影响产品范围确认，应在对应技术设计或开发任务中落实。
